## Core Type: LearningConcept

The central data type of the entire application. Every concept generated by the AI conforms to this interface. Every UI component, algorithm, and activity that touches a concept MUST consume the relevant fields — not hardcode alternatives.

```typescript
interface LearningConcept {
  // Identity
  id: string;
  name: string;
  stageId: string;
  order: number;
  icon?: string;

  // ========== TREE SYSTEM (REQUIRED) ==========
  tier: 'trunk' | 'branch' | 'leaf';      // LLM-declared, NOT computed
  parentName?: string;                      // Direct parent concept name
  trunkDomain?: string;                     // Top-level trunk this belongs to
  cognitiveLevel?: 'remember' | 'understand' | 'apply' | 'analyze' | 'evaluate' | 'create';
  lifecyclePhase: 'PREPARE' | 'MODEL' | 'DELIVER';
  dependencies: string[];                   // Concept IDs this depends on
  outdegree: number;                        // Count of concepts depending on THIS one
  commonPitfalls?: string[];                // Critical misconceptions (rendered in UI)
  connections?: Array<{
    target: string;
    type: 'requires' | 'enables' | 'is-part-of' | 'is-type-of' | 'causes' | 'constrains';
  }>;

  // ========== CORE CONTENT ==========
  hookSentence?: string;                    // Opening hook for learner attention
  whyYouNeed?: string;                      // Motivation for learning this concept
  howToUse?: string[];                      // Step-by-step application (from phase2)
  technicalDetails?: string;                // Deep technical explanation
  metaphor?: string;                        // Analogy for understanding (from microMetaphor)
  workedExample?: WorkedExample;            // Problem + solution + steps
  realWorldExample?: string;                // Real-world application

  // ========== METADATA ==========
  mnemonic?: MnemonicContext;               // Memory anchor system
  lifecycle?: ConceptLifecycle;             // 3-phase lifecycle with titles + steps
  shape?: ShapeContent;                     // SHAPE learning content (5 lenses)
  prerequisites?: string[];                 // Name-based prerequisite list
  keyPoints?: string[];                     // Summary bullet points
  perspectives?: CreatorPerspective[];      // Creator's Blueprint — approach switcher
}
```

## CreatorPerspective

The `perspectives` array powers the **Creator's Blueprint** switcher in the DrillDownCard. Each entry represents a different practitioner approach to the concept (e.g. Portal / CLI / Terraform for Azure, or Plaintiff / Defendant / Court for law).

```typescript
interface CreatorPerspective {
  label: string;      // e.g. "Portal", "CLI", "Terraform", "ARM/Bicep"
  blueprint: string;  // The creator's mental approach sentence for this method
  steps: string[];    // Actual atomic steps for this perspective (3-6 items)
}
```

**Data flow:** LLM generates `perspectives[]` → `json-parser.ts` extracts → `ParsedConcept.perspectives` → `transformer.ts` passes through → `LearningConcept.perspectives` → `buildMatrixPayload.ts` `buildPerspectives()` → `DrillDownAction.perspectives` → `CognitiveMatrixGridParts.tsx` renders pill switcher.

**Fallback:** If `concept.perspectives` is absent, `buildPerspectives()` synthesizes from `concept.lifecycle.phase1/2/3.steps`.

## Field Usage Contract

Every field below MUST be consumed by the specified system.

### Tree System Fields

| Field | Consumed By | How |
|-------|-----------|-----|
| `tier` | concept-selection.ts, interleaving.ts, MicroLearningLoopController | Tier badge, ordering weight, difficulty calc |

### Connection Types (Verb System)
```typescript
type ConnectionVerb = 'requires' | 'enables' | 'is-part-of' | 'is-type-of' | 'causes' | 'constrains';
```

| Verb | Meaning | Algorithm Use |
|------|---------|--------------|
| `requires` | Must learn target first | Prerequisite gate — blocks concept until target is complete |
| `enables` | Learning this unlocks target | Priority bonus — enablers are taught earlier |
| `is-part-of` | This is a component of target | Context bridge: "Let's zoom in" |
| `is-type-of` | This is a variant of target | Context bridge: "A specific variant" |
| `causes` | This triggers target | Context bridge: "Let's follow the chain" |
| `constrains` | This limits target | Context bridge: "Understanding the boundaries" |

## Bloom's Taxonomy Levels

| Level | Description | Difficulty Weight |
|-------|------------|------------------|
| `remember` | Recall facts | +0 |
| `understand` | Explain ideas | +0 |
| `apply` | Use in new situations | +1 |
| `analyze` | Break down into parts | +1 |
| `evaluate` | Justify decisions | +2 |
| `create` | Produce new work | +2 |

At least 60% of leaf concepts must be `apply` or higher. Backend enforces this via `_enforce_blooms_distribution()`.

## Subject Classification Types

```typescript
type SubjectType = 'procedural' | 'conceptual' | 'cyclic' | 'perceptual';
```

| Type | Pattern | Examples |
|------|---------|---------|
| `procedural` | Sequential stages on object lifecycle | Azure admin, surgery, coding |
| `conceptual` | Core moves + application patterns | Law, philosophy, music theory |
| `cyclic` | Fundamental cycle + meta-awareness | Design thinking, research, jazz |
| `perceptual` | Perceptual ladder + practice structures | Diagnosis, chess, art critique |

Used by: `perspectives` label guidance in prompt (Portal/CLI/Terraform for procedural cloud; Plaintiff/Defendant/Court for conceptual law, etc.)
